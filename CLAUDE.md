# CLAUDE.md

Руководство для Claude Code при работе в этом репозитории.

## 1. Обзор проекта

**Iron Roads** (`ironroads`) — мод для Minecraft 1.20.1 Forge, генерирующий
бесконечную сеть железных дорог поверх мира, построенную на путях мода Create.
Сеть — регулярная сетка магистралей с шагом 768 блоков, с развязками,
насыпями, эстакадами, тоннелями и плавными уклонами через кривые Безье Create.
Вся геометрия детерминирована: одинаковый сид и координаты всегда дают
одинаковый результат, независимо от порядка генерации чанков.

Проект в активной разработке (фаза 1–3 плана, см. раздел 4). Ядро — прямые
двухпутные магистрали с плавными уклонами и регистрацией в графе путей Create,
чтобы по дороге ехал поезд.

## 2. Технологический стек

- **Java 17**, Minecraft 1.20.1, **Forge 47.2.0** (dev), рантайм совместим с
  47.1.3+.
- **ForgeGradle 6** (`net.minecraftforge.gradle` `[6.0,6.2)`) + Parchment
  mappings (`2023.09.03-1.20.1`).
- **Create 6.0.8-291** — единственная жёсткая зависимость на сторонний мод.
  Подключается classifier `slim`; Ponder, Flywheel, Registrate, MixinExtras
  объявлены отдельными зависимостями с версиями, взятыми из
  `META-INF/jarjar/metadata.json` внутри jar'а Create — это не произвольный
  выбор, версии обязаны совпадать с тем, что Create несёт внутри себя.
- **JUnit 5** для юнит-тестов чистой геометрии, без Minecraft-раннера.
- Build: Gradle (`gradlew.bat` на Windows — `gradlew` без расширения в
  репозитории не работает из PowerShell, используйте только `.bat`).

## 3. Архитектурные правила

Это самое важное правило проекта, обязательное к соблюдению:

**Пакет `geometry` не импортирует ничего из `net.minecraft`, `com.simibubi`
или `net.minecraftforge`.** Классы `RailNetwork`, `TrackProfiler`,
`HeightSampler`, `Line` — чистая математика, тестируемая JUnit'ом без
поднятия игры. Связь с миром идёт через интерфейс `HeightSampler`
(`int heightAt(int x, int z)`), чья Minecraft-реализация
(`ChunkGeneratorHeightSampler`) живёт в `worldgen`. Перед тем как добавить
импорт из Minecraft в `geometry/*`, остановитесь — это архитектурная ошибка,
не мелочь.

**Два прохода, а не один.** Причина: `Feature.place()` не может трогать
соседние чанки (вызывает каскадную генерацию и дедлоки), а часть работы
(кривые Безье между чанками, регистрация путей в графе Create) требует
именно соседей.

1. `worldgen.RailwayFeature` (`Feature<NoneFeatureConfiguration>`) —
   worldgen-проход. Чистая функция от сида и координат чанка, кладёт блоки
   только внутри своих 16×16, оставляет разрывы под будущие кривые.
2. `graph.RailwayGraphLinker` — проход при загрузке чанка
   (`ChunkEvent.Load`), достраивает то, что требует соседей: кривые Безье
   через `SlopeLinker`, регистрация в `TrackPropagator`.

**Работа при загрузке чанка никогда не выполняется синхронно в колбэке.**
`ChunkEvent.Load` только кладёт `ChunkPos` в очередь; разбирает её
`onLevelTick` небольшими порциями (`PER_TICK`). Это не стиль, а
необходимость: колбэк загрузки держит блокировки чанковой системы, а
достройка сети требует читать соседние чанки — синхронный вызов внутри
колбэка вешает генерацию мира намертво. Это уже случалось на этом проекте
дважды за одну фазу; см. коммиты `70626e9` и дамп потоков в истории сессии.

**Геометрия детерминирована через хеш от координат, не `Random`.** Джиттер
пути (`RailNetwork`), выбор материала (`Palette`) — везде splitmix64 от
координат. `java.util.Random` с зерном по позиции здесь запрещён: он не даёт
той же гарантии независимости результата от порядка вызовов, которая нужна
для бесшовности на границах чанков.

**Никаких диагональных блоков пути и наклонных блоков 45° для плавных
уклонов.** Оба варианта проверены и отклонены в игре: диагональный путь
Create физически не стыкуется с прямым (разные точки стыка — середина грани
у прямого, угол у диагонального), а наклонный путь даёт уклон строго 45°,
который выглядит стеной. Единственный способ плавного поворота или уклона —
`BezierConnection` в `TrackBlockEntity`, создаваемая в `SlopeLinker`. Факты о
геометрии путей Create зафиксированы в
`docs/superpowers/plans/2026-07-25-railway-bezier-slopes.md` — читайте перед
любой правкой формы пути, там же точный API `BezierConnection`.

**Не гадать о производительности — мерить.** В `RailwayFeature.place()` уже
есть замер времени постройки чанка с порогом `SLOW_CHUNK_MILLIS`. Любая новая
дорогая операция (особенно всё, что трогает `ChunkGenerator.getBaseHeight` —
он строит целый `NoiseChunk` на каждый вызов и стоит на порядки дороже, чем
кажется) обязана либо кешироваться, либо не добавляться без замера.

## 4. Структура папок

```
src/main/java/dev/gensh/ironroads/
  geometry/   — чистая математика, ноль зависимостей от Minecraft, покрыта тестами
  worldgen/   — Feature, HeightSampler-реализация, укладка блоков, палитра материалов
  graph/      — проход при загрузке чанка: кривые Безье, регистрация в графе Create
  IronRoads.java — точка входа мода, регистрация фичи
src/main/resources/
  META-INF/mods.toml               — метаданные мода, зависимости
  data/ironroads/worldgen/         — configured_feature, placed_feature (JSON)
  data/ironroads/forge/biome_modifier/ — привязка фичи к биомам
src/test/java/dev/gensh/ironroads/
  geometry/   — юнит-тесты чистой геометрии
  worldgen/   — юнит-тесты детерминированных частей worldgen (напр. Palette)
docs/superpowers/
  specs/      — дизайн-документы
  plans/      — планы реализации по фазам, читать по порядку дат в имени файла
```

**Не трогать руками:** `run/`, `run-server/`, `build/`, `.gradle/` — всё
сгенерировано, в `.gitignore`. `gradle/wrapper/gradle-wrapper.jar` —
бинарник wrapper'а, не редактировать.

## 5. Стандарты кодирования

- Комментарии и Javadoc — **на русском**, следуйте существующему стилю.
  Комментарий объясняет **почему**, а не что: почти каждый нетривиальный
  комментарий в этом коде фиксирует отклонённую альтернативу или инвариант,
  который иначе неочевиден («не X, потому что Y» — сохраняйте эту форму).
- `final class` с приватным конструктором для чистых утилитных классов без
  состояния (`Palette`, `TunnelBuilder`, `SupportBuilder`).
- Константы конфигурации — `private static final int` рядом с классом, где
  используются, с комментарием, объясняющим выбор значения и что случится при
  его нарушении (см. `TrackProfiler.SLOPE_RUN`, `ENVELOPE_RADIUS`).
- Комментарии `ponytail: ...` отмечают намеренное упрощение с явной ценой и
  условием, когда его пересматривать. Не убирать эти комментарии при правке
  соседнего кода — они документируют осознанный компромисс, не долг.
- Кеши на потенциально многопоточных путях (worldgen многопоточен) —
  `ConcurrentHashMap`, не `HashMap`. Гонка при записи чистой функции безобидна
  (`RailwayProfilers`, `TrackProfiler`, `ChunkGeneratorHeightSampler`).

## 6. Backend-правила (worldgen / graph)

- `RailwayFeature.place()` обязан оставаться внутри границ своего чанка.
  Любая запись за `[chunkMinX, chunkMinX+16) × [chunkMinZ, chunkMinZ+16)` —
  баг, а не оптимизация: вызывает каскадную генерацию соседей.
- Профиль (`TrackProfiler`) должен быть **общим на весь мир** через
  `RailwayProfilers.forLevel(level, generator)`, ключ — сид. Не создавать
  `new TrackProfiler(...)` внутри кода, вызываемого на чанк или на тик —
  первое обращение к линии стоит тысячи выборок рельефа.
- `RailwayGraphLinker` и `RailwayFeature` обязаны строить **один и тот же**
  профиль (тот же `RailNetwork`, тот же `HeightSampler`) — иначе концы
  разрывов под кривые, вычисленные дважды, разойдутся и кривая не натянется.
- Любой новый строитель (по образцу `TunnelBuilder`, `SupportBuilder`) —
  статические методы без состояния, принимающие `WorldGenLevel`/`ServerLevel`
  и координаты явно. Не хранить `Level` в поле — экземпляр фичи переживает
  много чанков.
- Все константы геометрии магистрали (`SPACING`, `JITTER`, `MAX_GRADE_RUN`,
  `BED_HALF_WIDTH`, `TRACK_OFFSET`) объявлены `public static final` в
  `RailwayFeature` и переиспользуются в `graph/*` — не дублировать значения.

## 7. Frontend-правила

Не применимо — у мода нет клиентского UI за пределами стандартного рендера
блоков Minecraft/Create. Ресурсы (`blockstates`, модели, текстуры) для
собственных блоков не заведены — мод использует существующие блоки Create и
ваниллы.

## 8. Правила работы с данными (datapack JSON)

- `data/ironroads/worldgen/placed_feature/railway.json` держит **пустой**
  `placement` намеренно — фича сама решает, проходит ли линия через чанк;
  любой ванильный placement-модификатор добавил бы случайность, разорвав
  детерминированную сеть.
- `data/ironroads/forge/biome_modifier/railway.json` привязывает фичу ко всем
  оверворлд-биомам (`#minecraft:is_overworld`) на шаге
  `top_layer_modification`.
- Правка `mods.toml`: `[[dependencies.ironroads]]` на `create` обязана
  оставаться `ordering = "AFTER"` — фича обращается к блокам Create, они
  должны зарегистрироваться раньше.

## 9. Правила безопасности

Мод не работает с сетью, файловой системой за пределами стандартного
Minecraft save API, вводом пользователя как с недоверенным источником или
секретами. Специфичных для проекта требований безопасности нет за пределами
обычной осторожности с NBT/сохранениями Minecraft.

## 10. Правила работы с базой данных

Не применимо — постоянное состояние ограничено стандартными Minecraft-save
данными (чанки, блоки, `TrackBlockEntity` от Create). Отдельной БД нет.
`LinkedChunks` — набор посещённых чанков **в памяти**, намеренно не
персистентный (см. Javadoc класса); не путать с постоянным хранилищем и не
превращать в него без явного запроса — таков текущий компромисс.

## 11. Тестирование

- Запуск: `.\gradlew.bat test` (все) или `.\gradlew.bat test --tests
  '*ИмяТеста*'` (точечно).
- Тестируется только `geometry/*` и детерминированные части `worldgen/*`
  (`Palette` — через `PaletteHashTest`, который дублирует хеш-функцию
  локально, чтобы не тянуть classpath Minecraft ради теста хеша — этот
  паттерн предпочтителен для любого нового чистого алгоритма внутри
  MC-класса).
- Обязательные инварианты, уже покрытые тестами — не ослаблять при правке
  геометрии:
  - Профиль высоты никогда не переходит из подъёма сразу в спуск в одной
    точке (`profileNeverSpikes`) — иначе наклонные блоки Create не
    состыкуются.
  - Развязка на узле решётки лежит на одной высоте для обеих пересекающихся
    линий (`crossingLinesAgreeOnHeight`, `crossingsSitOnLevelGround`).
  - Разрыв под кривую никогда не касается границы отрезка и никогда не
    накрывает узел решётки (`rampStaysInsideItsSegmentAndOffCrossings`).
  - Одинаковый сид и позиция дают одинаковый результат независимо от
    экземпляра/порядка вызова (`sameSeedAndPositionGiveSameResult`,
    `profileIsPositionLocalNotPathDependent`).
- Для новых тестов на "не вырождается ли в тривиальный случай" — см.
  `assertTrue(changes > 20, ...)` в `TrackProfilerTest` и
  `allVariantsGetUsed` в `PaletteHashTest`: тест обязан явно проверить, что
  сценарий не прошёл вхолостую (например, что профиль не оказался плоским).
- Ручная проверка в игре (визуальная связность, отсутствие зависаний)
  обязательна для любой правки `worldgen`/`graph` — юнит-тесты не ловят
  визуальные разрывы путей или производительность в реальном мире.
  `.\gradlew.bat runClient`, новый мир (старые сохранения содержат чанки от
  прошлой версии кода).

## 12. Правила развёртывания

- Сборка: `.\gradlew.bat build` → jar в `build/libs/`.
- Локальный тестовый запуск: `.\gradlew.bat runClient` — **обязательно** с
  `.bat`, простой `gradlew` не работает из PowerShell/cmd на этой машине.
- Первый запуск декомпилирует Minecraft, занимает 5–15 минут — это нормально,
  не признак зависания.
- Обязательные свойства в `runs.configureEach` (`build.gradle`) —
  `mixin.env.remapRefMap` и `mixin.env.refMapRemappingFile` — не убирать: без
  них миксины Ponder/Flywheel падают на старте в dev-окружении с
  `InvalidInjectionException`.
- Публичный релиз мода требует `create` (модId, версия из `mods.toml`)
  установленным отдельно — это обязательная (`mandatory = true`) зависимость,
  не бандлится.

## 13. Правила экономии токенов

- Перед любой правкой геометрии путей или укладки блоков прочитать
  `docs/superpowers/plans/2026-07-25-railway-bezier-slopes.md` — там уже
  проверены и задокументированы факты об API Create (`TrackShape`,
  `BezierConnection`, `TrackBlockEntity`), полученные чтением jar'а. Не
  добывать их заново декомпиляцией/поиском — это дорого и уже сделано.
- При подозрении на зависание/производительность в `worldgen`/`graph` —
  сначала смотреть, не изменилась ли стоимость `HeightSampler.heightAt`
  (обёртка над `ChunkGenerator.getBaseHeight`, дорогая операция с историей
  зависаний в этом проекте) или не появился ли синхронный вызов внутри
  `ChunkEvent.Load`. Это два известных класса причин, оба уже случались.
- Файлы `docs/superpowers/plans/*.md` — источник истины по состоянию задачи и
  причинам прошлых решений; при продолжении работы читать последний по дате в
  имени файла целиком до того, как писать код.
